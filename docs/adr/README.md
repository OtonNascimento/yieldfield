# Architecture Decision Records

Each ADR records one decision, why it was made, and what it supersedes. ADRs exist
because PROJECT_CONTEXT §0 makes the locked stack decisions **overridable, but only with
a trail** (ARCHITECTURE `docs/adr/`).

Format per file: Context → Decision → Consequences → Status, with a link to the governing
PROJECT_CONTEXT / ARCHITECTURE section(s). Files are numbered and never renumbered; a
reversed decision gets a new ADR that supersedes the old one.
