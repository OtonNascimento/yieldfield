## Why this matters

The repo's binding docs require the frontend API client to be **generated from
`contracts/openapi/openapi.json`, never hand-written** (docs/IMPLEMENTATION_PROMPT.md,
"Typed end to end" hard invariant; docs/PROJECT_CONTEXT.md §10). Today nothing
implements that: there is no generator dependency, no npm script, and no
TypeScript path by which anything under `contracts/generated/` could even be
imported from `frontend/` (`contracts/generated/` holds only a `.gitkeep` reading
"Generated typed client is emitted here in Slice 4"). Slice 4 — the next slice,
whose first step is "generate the typed client from contracts/" — stalls or
improvises a hand-written client unless this lands first. This plan wires the
lightest compliant pipeline: `openapi-typescript` (types-only, zero runtime),
an `npm run generate:api` script, a `@contracts/api` path alias, a committed
generated artifact, and a CI drift gate.

## Steps

### Step 1: Add the generator dependency and script

In `frontend/package.json`:

- devDependencies: add `"openapi-typescript": "^7.4.0"` (or current v7 minor).
- scripts: add
  `"generate:api": "openapi-typescript ../contracts/openapi/openapi.json -o ../contracts/generated/typescript/api.d.ts"`.

Run `npm install`.

**Verify**: `npm run generate:api` → exit 0 and
`contracts/generated/typescript/api.d.ts` exists and is non-empty (it should
export `paths`/`components` interfaces mirroring the schema — spot-check that
`"/api/v1/findings"` appears in it).

### Step 2: Make the artifact importable via a path alias

In `frontend/tsconfig.app.json` `compilerOptions.paths`, add:

```json
"@contracts/api": ["../contracts/generated/typescript/api.d.ts"]
```

Create `frontend/src/shared/api/index.ts`:

```typescript
// The generated contract types (§10): the ONLY sanctioned way frontend code
// names API shapes. Runtime client wiring lands in Slice 4; this module is
// type-only until then.
export type { paths, components } from '@contracts/api';
```

Use `export type` / `import type` exclusively — type-only imports are erased at
compile time, which is why neither Vite config nor bundler settings change.

**Verify**: `npm run typecheck` → exit 0. This simultaneously answers the known
open question about `exactOptionalPropertyTypes` (tsconfig line 28) against the
generated types — if it errors here, see STOP conditions.

### Step 3: Full frontend gates

**Verify**: `npm run lint` → 0; `npm run format:check` → 0 (if Prettier flags
the new file, run `npm run format` and re-check); `npm run test` → pass;
`npm run build` → 0.

### Step 4: CI drift gate

In `.github/workflows/ci.yml`, in the `frontend` job after "Install
dependencies", add:

```yaml
      - name: "Generated client matches the contract (drift fails the build, §10)"
        run: |
          npm run generate:api
          git diff --exit-code -- ../contracts/generated
```

**Verify**: the YAML sanity command from the table → `yaml ok`. Then locally
simulate the gate: `npm run generate:api` followed by
`git diff --exit-code -- ../contracts/generated` → exit 0 (no drift, because you
committed the artifact in this same change).

### Step 5: Replace the placeholder marker

Delete `contracts/generated/.gitkeep` only if git still tracks the directory via
the new committed artifact (it will). Update `contracts/README.md` ONLY if it
contains a sentence contradicted by this change — read it first; if its claims
remain true (frontend imports the generated client), leave it untouched.

**Verify**: `git status` shows exactly the in-scope files.

## STOP conditions

Stop and report back (do not improvise) if:

- `npm run typecheck` fails in Step 2 with errors inside or against the
  generated `api.d.ts` (most likely `exactOptionalPropertyTypes` friction —
  TS2375/TS2412 — or `composite`-project file-inclusion errors TS6059/TS6307).
  Report the exact errors plus the two candidate resolutions for the
  maintainer's choice: (a) emit into `frontend/src/shared/api/generated/`
  instead (deviates from the `.gitkeep`'s stated home — requires their
  sign-off), or (b) relax the specific tsconfig flag for the generated file.
  Do NOT pick unilaterally.
- `openapi-typescript` cannot parse the committed schema (would indicate schema
  or version drift — do not hand-edit either side).
- The eslint boundary rules flag the new shared module — do not add
  rule exemptions; report instead.
